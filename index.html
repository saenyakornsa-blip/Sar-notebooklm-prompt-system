  • DNA 1 ตรวจความสอดคล้องภายใน (Internal Consistency) — จุดเด่นกับจุดด้อยต้องไม่ขัดแย้งกัน เช่น บอกว่า "พัฒนาการดีครบ 4 ด้าน" แต่จุดด้อยบอกว่า "ขาดกระบวนการทางคณิตศาสตร์" — ถือว่าขัดแย้งกัน
  • DNA 2 ตรวจหลักฐานเชิงประจักษ์แบบ Actionable — ต้องระบุเป็นข้อๆ ชัดเจน แยกรายมาตรฐาน รายระดับ พร้อมชื่อเอกสารจริง ไม่ใช่แค่กล่าวถึงรวมๆ เป็น Wall of Text ท้ายเล่ม
  • DNA 3 ตรวจความเป็นวิชาการของภาษา — ภาษาต้องเป็นทางการ เช่น "ปูพื้นฐานการอ่านออกเขียนได้" → แก้เป็น "กำหนดแผนงาน/โครงการ/กิจกรรมเพื่อพัฒนาทักษะพื้นฐานด้านการอ่าน การเขียน และการคิดคำนวณ"
  • DNA 4 ตรวจความน่าเชื่อถือของตัวเลข — เป้าหมายกับผลสำเร็จเท่ากันเกือบทุกโครงการ หรือผล 100% ทุกรายการ → ตั้งคำถามว่าประเมินจริงหรือเปล่า ต้องสมเหตุสมผลตามบริบทจริง
  • DNA 5 ตรวจความถูกต้องของหลักสูตร/วันที่/การสะกด — หลักสูตรปี 2565 นำมาใช้ปี 2568 = ไม่มีการพัฒนา, วันที่ประกาศต้องถูกต้องตามปีการศึกษา, ตัวเลขไทยและอารบิกไม่ควรปะปนกัน

===แหล่งข้อมูลใน Notebook นี้===
Zone A: เกณฑ์มาตรฐาน สมศ. รอบ 5 · กรอบแนวทางจัดทำ SAR · ตัวบ่งชี้และค่าเป้าหมาย
Zone C: คู่เอกสาร SAR + ไฟล์แก้ไขจากผู้ทรงคุณวุฒิจริง (Before/After · 3–4 ชุด) → ใช้เรียนรู้สไตล์การตรวจ
Zone D: SAR โรงเรียนเป้าหมายที่ต้องตรวจวันนี้ → วิเคราะห์แยกทีละโรง ครบทุกไฟล์ใน Zone D

===หลักการตรวจที่ต้องยึดถือ (DNA 5 รูปแบบ)===
DNA 1: ตรวจความสอดคล้องภายใน — จุดเด่นกับจุดด้อยต้องไม่ขัดแย้งกัน
DNA 2: ตรวจหลักฐานเชิงประจักษ์ — ต้องระบุเป็นข้อๆ แยกรายมาตรฐาน ไม่รวบไว้ท้ายเล่ม
DNA 3: ตรวจความเป็นวิชาการของภาษา — ต้องเป็นทางการ ไม่ใช้ภาษาพูดหรือภาษาเรียงความ
DNA 4: ตรวจความน่าเชื่อถือของตัวเลข — เป้าหมาย = ผลสำเร็จ 100% ทุกโครงการ = ตั้งข้อสังเกต
DNA 5: ตรวจความถูกต้องทางเทคนิค — หลักสูตร วันที่ ปีการศึกษา การสะกด ตัวเลขไทย/อารบิก

===รูปแบบการให้ข้อเสนอแนะ===
- ตรงไปตรงมา ไม่ปรานี แต่สร้างสรรค์ ไม่ใช้ภาษาปลอบใจ
- ระบุตำแหน่ง/หน้า/มาตรฐานที่พบปัญหาให้ชัดเจน
- เสนอตัวอย่างการแก้ไขที่เป็นรูปธรรมทุกครั้ง
- อ้างอิงสไตล์ผู้ทรงฯ จาก Zone C เมื่อพบรูปแบบปัญหาที่คล้ายกัน

⚠ ห้ามนำข้อมูลโรงเรียนจาก Zone C มาปนกับ Zone D

1. ความครบถ้วนของส่วนประกอบ SAR (เทียบ Zone A)
   - บทสรุปผู้บริหาร: ครบทั้ง 2 ระดับ (ปฐมวัย + ขั้นพื้นฐาน) หรือไม่ / จัดรายมาตรฐานหรือเป็นความเรียง
   - ส่วนที่ 1–4 ครบตามที่ สมศ. รอบ 5 กำหนดหรือไม่
   - มีระบุระดับคุณภาพ (ดีเลิศ/ดีมาก/ดี/พัฒนา) อย่างชัดเจนหรือไม่

2. บทสรุปผู้บริหาร
   - สรุปครบทุกมาตรฐานเป็นรายข้อหรือไม่
   - มีแผนพัฒนาตนเองระบุเป็นข้อๆ หรือไม่

3. หลักฐานสนับสนุน (DNA 2)
   - รายการหลักฐานระบุเป็นข้อๆ แยกรายมาตรฐานหรือเป็น Wall of Text
   - มีชื่อเอกสารจริงอ้างอิงหรือแค่ชื่อโครงการรวมๆ

4. ความถูกต้องทางเทคนิค (DNA 5)
   - หลักสูตรที่ใช้อ้างอิงตรงกับปีที่รายงานหรือไม่
   - วันที่ ปีการศึกษา ตัวเลขไทย/อารบิก ถูกต้องสม่ำเสมอหรือไม่

5. เทียบ Zone C — ปัญหาโครงสร้างที่คล้ายกับที่ผู้ทรงฯ เคยแนะนำ

ส่วนที่ 1: ตรวจความน่าเชื่อถือของตัวเลข (DNA 4)

รวบรวมตัวเลขเป้าหมายและผลสำเร็จทุกรายการ แล้วตอบ:
  - รายการที่เป้าหมาย = ผลสำเร็จพอดี หรือ 100.00% ทุกโครงการ มีกี่รายการ
  - ตัวเลขเหล่านั้นสมเหตุสมผลตามบริบทจริงหรือไม่
  - ค่าเบี่ยงเบนที่ควรมีตามธรรมชาติการประเมินเป็นอย่างไร

สัญญาณอันตราย ที่ต้องรายงาน:
  🔴 ผลสำเร็จ 100% ในทุกโครงการหรือทุกมาตรฐาน
  🔴 ตัวเลขนักเรียนในโครงการ = จำนวนนักเรียนทั้งหมด ทุกโครงการ
  🔴 ค่าเป้าหมายและผลสำเร็จเป็นตัวเลขเดียวกันทุกรายการ

ตัวอย่างคำแนะนำแก้ไขที่ควรให้: [ระบุตัวอย่างจริงจาก SAR นี้]

G3 คู่มือการใช้งาน Layer 2 ขั้นตอนตั้งแต่ P5 → Gap Report
GUIDE ขั้นตอนการตั้งค่าและใช้งาน Gemini Gem ▶
ทำตามขั้นตอนนี้ครั้งแรกครั้งเดียว จากนั้นใช้ซ้ำได้ทุกเครือข่าย
STEP 1 — ตั้งค่า Gem (ครั้งเดียว)
1. เปิด gemini.google.com → คลิก "Gems" ในแถบซ้าย
2. คลิก "New Gem" → ตั้งชื่อว่า "SAR Gap Report — นครราชสีมา"
3. วาง System Prompt จาก SYS ด้านบนในช่อง "Instructions"
4. คลิก "Save" → Gem พร้อมใช้งาน
STEP 2 — ส่ง Input ทุกครั้ง
1. เปิด Gem "SAR Gap Report — นครราชสีมา"
2. Copy SAR Fact Sheet ทั้งหมดจาก NotebookLM P5 (ทุกโรงในรอบนั้น)
3. วางใน Template G2 แทนที่ [วาง Fact Sheet ที่นี่]
4. ส่ง → รอ Gap Report ครบ Section A–E
STEP 3 — ถ้าตัวอย่างไม่เฉพาะเจาะจงพอ
ส่ง Follow-up Message:
follow-up · ขอตัวอย่างเฉพาะเจาะจงขึ้น 
สำหรับ Gap "[ระบุ Gap ที่ต้องการ]" ของ[ชื่อโรงเรียน]
ขอตัวอย่างที่เฉพาะเจาะจงขึ้น โดยใช้:
- ชื่อโครงการจริงจาก Fact Sheet: [ระบุชื่อโครงการ]
- ตัวเลขจริงที่ปรากฏ: [ระบุตัวเลข]
- มาตรฐานที่เกี่ยวข้อง: [มาตรฐานที่ X]

เขียนตัวอย่าง ❌ (ที่มีอยู่) และ ✅ (ที่ควรเป็น) ให้ครบโดยใช้บริบทข้างต้น
💡 Tips: Gemini Gem มี Context Window ใหญ่กว่า NotebookLM — ใส่ Fact Sheet ได้ 8–10 โรงต่อครั้ง · ถ้าต้องการ Output เป็น Markdown สำหรับ copy ไปทำรายงาน ให้เพิ่ม "ตอบเป็น Markdown ทั้งหมด" ใน G2 Template
